# VeriDrift

VeriDrift is a standalone reproduction package for federated node-classification backdoor defense experiments. The package contains the training, attack, partitioning, risk estimation, and consistency-verification logic needed to run the supported node-classification experiments. Generated datasets, partitions, checkpoints, and analysis outputs are written under local ignored directories.

## Project Structure

```text
veridrift/
  configs/
    generated_main/              # Batch-generated configs, ignored except .gitkeep
  data/                          # PyG datasets, downloaded on demand and ignored
  partitions/                    # Generated or precomputed client partition metadata
  outputs/                       # Run outputs, checkpoints, metrics, and logs
  analysis_outputs/              # Summary CSV/Markdown outputs
  src/
    attack.py                    # Renyi, BA, WS, and GTA-style trigger construction
    data.py                      # Dataset loading, splits, partitions, and local subgraphs
    federated.py                 # Local client training and weighted aggregation
    model.py                     # GCN backbone
    risk_credit.py               # Client-side cross-layer drift risk estimation
    rscc_certifier.py            # Server-side consistency verification and weighting
    server_certifier.py          # Legacy certifier kept for compatibility experiments
    utils.py                     # Runtime path, seed, device, YAML/JSON helpers
  train_fgl_node_risk.py         # Single-run training entrypoint
  run_main_experiments.py        # Batch experiment runner
  runner_common.py               # Shared dataset, partition, trigger, and config helpers
  table_output_layout.py         # Organized output path helpers
  summarize_main_experiments.py  # Main sweep summarizer
```

## Environment

The code was tested with Python 3.10, PyTorch 2.0.1, PyTorch Geometric 2.6.1, CUDA 11.7, NumPy 1.26.3, pandas 2.2.2, scikit-learn 1.6.1, and NetworkX 3.2.1.

Example setup:

```bash
conda create -n veridrift python=3.10 -y
conda activate veridrift

# Install PyTorch for your CUDA/CPU platform.
pip install torch==2.0.1 --index-url https://download.pytorch.org/whl/cu117

# Install PyTorch Geometric and common scientific dependencies.
pip install torch-geometric==2.6.1
pip install numpy pandas scikit-learn networkx pyyaml
```

If your CUDA version differs, install the matching PyTorch and PyG builds from the official PyTorch/PyG instructions.

## Datasets

VeriDrift uses PyTorch Geometric datasets. The following datasets are supported:

- Cora
- CiteSeer
- PubMed
- Coauthor CS
- Coauthor Physics
- Amazon Photo

The datasets are downloaded automatically into `data/` the first time a run needs them:

```bash
python train_fgl_node_risk.py --config configs/cora_node_iid_renyi.yaml --device cuda --max-rounds 100
```

`data/` is ignored by Git because the raw/processed datasets can be large.

Outputs are written to:

```text
outputs/<timestamp>_<dataset>_node_<partition>_<trigger>/
```

Each run contains `config.json`, `metrics.csv`, `final_metrics.json`, risk-credit logs, server-certifier logs, and checkpoints.

## Single Experiment

To run the default Cora IID Renyi-trigger experiment for all configured rounds:

```bash
python train_fgl_node_risk.py \
  --config configs/cora_node_iid_renyi.yaml \
  --device cuda
```

You can edit the YAML file to change the dataset, partition, attack trigger, malicious-client fraction, training rounds, or output directory.

## Batch Experiments

`run_main_experiments.py` generates configs under `configs/generated_main/` and launches `train_fgl_node_risk.py` repeatedly.

Example:

```bash
python run_main_experiments.py \
  --device cuda \
  --datasets Cora PubMed CiteSeer \
  --partitions iid louvain \
  --triggers renyi \
  --malicious-fractions 0.3 \
  --seeds 42 43 44 45 46
```

Generated batch outputs are organized under:

```text
outputs/organized_table_results/
```

The exact nested output path is derived from the dataset, partition, trigger, malicious-client fraction, and optional partition skew parameter.

## Summaries

For simple single-run-style output folders under `outputs/`, summarize completed runs with:

```bash
python summarize_main_experiments.py \
  --outputs-dir outputs \
  --output-dir analysis_outputs
```

This writes CSV and Markdown summaries into `analysis_outputs/`.

## Notes

- `outputs/`, `analysis_outputs/`, `data/`, and generated partition metadata are ignored by Git.
- `configs/generated_main/*.yaml` is ignored because these files are generated by the batch runner.
- `partitions/` is created locally so repeated runs can reuse the same client splits when matching metadata files are present.
